# 来源与时效：内容质量的形式化抓手（设计，待审）

> 用户内容的本质:**来源驱动**——最佳实践、cheatsheet、基于已有东西快速上手/了解,少部分深度研究但带大量来源佐证。**每篇都有一个或多个来源/引用,且必须有外部链接方便查源、判断是否过时。**
>
> 这带来一个关键转折:上一层(机器兜底)说"内容对不对机器兜不住",但**内容可信度里"有没有来源、来源活不活、过没过时"是可机器查的**。所以这把"内容质量"从纯人审拉回一大块到可机器辅助。

## 能机器化 vs 仍需人审（划清边界）

| 内容质量的这部分 | 谁兜 |
|---|---|
| 有没有来源支撑 | **机器**(Schematron 强制) |
| 来源链接还活着吗(404) | **机器**(链接活性检查) |
| 多久没核对、过没过时 | **机器**(核对日期 + volatility) |
| 来源本身说的对不对 | 人(机器不懂) |
| 你的总结/提炼准不准、有没有曲解来源 | 人 / AI 交叉验证 |

**机器把"可信度的形式条件"兜住(有据可查 + 据还在 + 标了时间),人只审"提炼准不准"。**

## 来源在 DITA 里怎么表达

按你的内容分两种密度:

- **一两个主来源**(cheatsheet/最佳实践):prolog 里 `<source href="..."/>`(标准元数据,可查询)+ prolog `<critdates><reviewed date="..."/>`(核对日期)
- **大量来源**(深度研究):正文末尾一个"来源"`<section>`,内含多个 `<xref href="..." scope="external"/>`——像 dita2 笔记末尾那种"已核对/未核对"分档的来源节
- **正文就近引用**:论断处直接 `<xref scope="external" href="...">` 指源

关键:**所有外部来源统一用 `scope="external"` 标记**——这样链接活性检查能一键提取所有外链去查。

## 机器化三件（并入机器兜底）

1. **Schematron 强制来源**(新增规则,记作 R8):concept/reference **必须有至少一个来源**(prolog source 或来源节的外链)。没来源的内容报错——因为你的内容本就该有出处。
2. **链接活性检查**(机器兜底新增一层):脚本提取所有 `scope="external"` 的 href → 批量 HEAD 请求 → 报 404/失效/重定向。这是"笔记过时"的硬信号之一(源没了 = 该复核)。
3. **时效联动**:`reviewed` 日期 + `volatility` → volatile 且来源很久没核对 → 提醒复核。对接已有的成熟度/时效纪律(volatile 无核对日期不得 verified)。

## 这条与已有的关系

不是全新——dita2 的**来源纪律**(每篇分"已核对/未核对")+ **volatility 维度**已经覆盖了一半。这里是把它**机器化 + 强制化**:
- 原来"来源分档"是写作约定 → 现在 Schematron 强制有来源
- 原来"链接易腐"是提醒 → 现在链接活性检查主动查
- 原来"核对日期"是自觉 → 现在时效联动提醒

## 落地（并入第一批的机器兜底）

- Schematron 加 **R8(必须有来源)**
- `kb/scripts/link-check.*`:提取外链 → 批量查活性 → 报失效(并入 review.sh)
- 来源元数据规范:主来源 prolog source、多来源末尾来源节、统一 `scope="external"`
