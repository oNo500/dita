# 阶段总结（2026-08-09）

> 这一段从"维度完整性方法"一路做到"术语库首批"，把知识体系重塑的第一批工具链地基基本落齐、逐件验证过。设计文档在本目录，成品在 ~/code/kb。

## 一、做完的四块

### 1. 维度体系（从方法到可跑的数字，完整闭环）
- **方法**：梳理任何领域，先对标建立完整维度框架（防被已知蒙蔽），再在完整框架上按 80/20 切出快速上手。维度完整性是领域级建设纪律，不是贯穿每篇的主线。
- **对标**：五路（矿场实据 + 技术制品 + 工程治理 + AI + 写作），归纳出领域**四族**（技术制品/工程治理/AI构建/方法规范）× 维度**两层**（通用核心 + 族特有）。矿场补出外部框架都没有的个人维度（换栈差异等）。
- **落地**：词表升 v0.3，加横切 `dimension` 值集（45 键 + 按需补的 `dim-packaging`）。维度标引用 `@dimension` 专门化属性（见第二节坑）。
- **验证**：领域全景样板 `electron-landscape` + 覆盖度脚本 `dimension-coverage.py`，实测 0/10 → 2/10。
- **治理**：`bm-dimension` 登记，维度值集本身进防过时机制。

### 2. Schema 与机器兜底
- **四个 shell**：`concept/reference/glossentry-kb` + 四个属性域（maturity/volatility/tool/dimension）。造 shell 前先核对 DITA-OT 实际模块（不猜 URN/依赖）。
- **机器兜底主干**：`rules.sch`（R1–R10 规格）+ `check-rules.xsl`（自带 Saxon 可执行）+ `review.sh`（一条命令串 RNG 结构 + 业务规则 + 覆盖度，有 error 退出非零）。跑通，还当场抓出 7 篇试点 topic 真实缺来源。

### 3. 术语 + 双语两条主线（用户定的最高优先）
- **双语形态定稿**：中文单源 + 术语库双语条目 + 英文 AI 按需翻（方案 A 起步、留口 B）。
- **术语库首批**：矿场 30-06 的 27 条按重塑甄别 → 通用 9 + 工具名 3 = **12 条双语 glossentry**，弃 18 条 Obsidian 特有（重塑非迁移）。挂进 glossary map，`keys=term-*` 供 `<term keyref>` 引用。

### 4. 决策定案（按推荐通过）
- 双语 4 点、Schematron 4 点全定；R7 术语库建成即激活；核对日期用 `data name="reviewed"`。

## 二、一条贯穿的纪律：别拍脑袋，验证到底

这一段最大的收获不是某个产出，是一条被反复印证的纪律——**能过 validate ≠ 用对 DITA；规范假设不查证就是错的**。踩过并纠正的坑：

- 维度标引：先误用 topic 根 `@subjectrefs`（非法）→ 改 prolog `data`（能过 validate 但丢语义）→ 查 DITA 2.0 规范发现 **classification domain 被移除** → 正道是 `@props` 专门化 `@dimension`（回到自家三属性域的成熟模式）。用户一句"这是怎么了"把方案从错路上拽回。
- 核对日期：先拍 `critdates/reviewed` → 样板 validate 报错（DITA `critdates` 无 `reviewed` 元素）→ 改 `data name="reviewed"`。
- 造 shell、建术语库前，都先去 DITA-OT 实际模块 / 矿场原文核对，不凭记忆。

## 三、现在到哪了 / 下一步

**第一批工具链地基基本齐**：四 shell + 维度体系 + 机器兜底（结构/业务规则/覆盖度）+ 术语库首批 + 双语形态。
