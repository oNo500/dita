# 机器兜底工具链（设计，待审）

> AI 主笔模型下,DITA 质量全靠机器兜。这套兜底的关键定位:**不只是"人工审查的替代",是"给 AI 的反馈回路"**——机器检查的输出给 AI 读,AI 自己修,形成"AI 写 → 机器检 → AI 修"的闭环,人只审最后一版。

## 两类动作：检查报错 + 自动修正

机器兜底不全是"报错让人改",有一部分是"直接自动修":

- **检查报错**(结构/业务规则/链接/受控值):机器发现问题 → 报告 → AI 或人修
- **自动修正**(术语规整):机器直接把 AI 写的字面词换成 keyref,不用报错让谁改

## 五层检查

| 层 | 工具 | 兜 AI 什么错 | 动作 | 现状 |
|---|---|---|---|---|
| **1 结构** | `dita validate`(kb shell 的 RNG) | 元素顺序/缺必需元素/非法元素/属性非法 | 报错 | ✅ 有(concept-kb 验证过) |
| **2 业务规则** | Schematron R1–R10 + Saxon | 缺 shortdesc、volatility 没标、verified 无日期、受控值非法 | 报错 | ⬜ 设计了(schematron-设计.md),待落地 |
| **3 术语** | 后处理脚本(读术语库) | 术语带偏(别名/简称/全称乱用) | **自动修**(字面词→keyref) | ⬜ 待建 |
| **4 链接** | `dita` 构建 / 专门检查 | xref/conref/keyref 指向不存在 | 报错 | ✅ 构建报(有) |
| **5 受控值** | subjectScheme(构建期) + Schematron R4–6(编辑期) | @subjectrefs/@maturity/@tool 值不在词表 | 报错 | ✅/⬜ 构建期有、编辑期待落地 |

## 第 5 层附带：维度覆盖度报告

受控值层还产出一份维度覆盖度报告(不是报错,是报告):读各领域全景的 `planned-dimension` 清单,对每个维度查有没有内容 topic 用 `@dimension` 覆盖,算出覆盖度、列出盲区。给 AI 和你看该补哪些维度。**已落地**:`kb/scripts/dimension-coverage.py`,按 `data name="domain"` 分组、支持多值 `@dimension`;electron 样板验证 0/10 →(标一篇覆盖两维)2/10。依据见 维度完整性-方法与约束.md。

## 管线：AI 写 → 兜底 → 自修 → 入库

```
AI 写完 .dita
   ↓
review.sh（一条命令跑全套）
   1. 术语后处理：字面词 → keyref（自动修，先修再检）
   2. dita validate：结构（RNG）
   3. Schematron：业务规则 R1–R10
   4. 链接检查：断链
   5. 受控值：subjectrefs/maturity/tool 在词表内
   ↓
结构化报告（文件:行 + 问题 + 严重度 + 修法）
   ↓
error 有 → AI 读报告自修 → 再跑 review.sh   ← 闭环
error 无 → 入库
```

## 关键设计

1. **报告要给 AI 消费**(不只给人看)。因为 AI 是主笔,报告结构化(文件:行 + 问题 + 严重度 + 建议修法),AI 读了能**自己修**。这是 AI 主笔特有的强设计:大部分错在入库前被 AI 靠机器反馈自己修掉,人只审最后。
2. **术语后处理依赖术语库登记全叫法**。后处理靠什么认出"AI 用的乱叫法"?靠术语库每个 term 登记了**首选词 + 别名 + 简称 + 全称**(中英都要)。扫正文,匹配到任一叫法 → 换成该 term 的 keyref。**所以术语库不能只有首选词,要含别名/简称/全称**——这直接约束了 glossentry 的结构。
3. **分级**:error(必修,阻断入库) / warning(建议,不阻断)。
4. **集成三档**(按需上):
   - 手动 `review.sh`(AI 写完跑,最先做)
   - git pre-commit hook(提交前挡不合格的)
   - CI(push 跑,团队/多机)
